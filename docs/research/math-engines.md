# Math engines for a handcalcs-style structural calc app (web/PWA + CLI)

Research date: 2026-10-15. Primary sources only (official docs, source files, npm registry, GitHub API). Every claim links to where it came from. Nothing downloaded was executed.

Context: the document format is Markdown prose + math statements (variables, formulas, units), evaluated top-to-bottom, results shown inline, PDF report with KaTeX rendering of *symbolic formula -> substituted values -> result* (handcalcs style). The working assumption to test: "math.js covers everything."

Short answer: **math.js covers evaluation, units, matrices and LaTeX-ish output well enough to build on, but it is not a CAS (no `solve`, no `integrate`), its `toTex` has three concrete gaps for engineering notation (underscore subscripts, unit names colliding with variable names, no unit-aware LaTeX), and its unit formatter will happily print a bending moment as joules.** Details and the recommendation at the end.

### Expression parser, scope, variables, custom functions

- `math.evaluate(expr, scope)`, `math.compile(expr).evaluate(scope)`, `math.parse(expr)` -> node tree, `math.parser()` with persistent scope. Scope may be a `Map` (recommended; "allows any variable or function name"), a plain object (checked against a symbol blacklist), or any object with `get/set/has/keys`. [parsing](https://mathjs.org/docs/expressions/parsing.html)
- Assignments and function definitions inside expressions: `c = 2.3 + 4.5`, `f(x, y) = x^y`. "Such function assignments are limited: they can only be defined on a single line." Multi-statement blocks separated by `\n` or `;`; lines ending in `;` are evaluated but hidden; result is a `ResultSet`. Comments start with `#`. [syntax](https://mathjs.org/docs/expressions/syntax.html)
- Identifier rule (from source): first char must match `/^[a-zA-Z_$À-ʯͰ-Ͽ℀-⅏]$/` (Latin, `_`, `$`, accented Latin, **Greek block U+0370-03FF**, letter-like symbols) or a `\uD835` math-alphanumeric surrogate pair; digits allowed after the first char. Reserved: `mod to in and xor or not end`. So `M_Ed`, `f_yd`, `γ_M0`, `α` are all valid identifiers. [parse.js](https://raw.githubusercontent.com/josdejong/mathjs/develop/src/expression/parse.js), [syntax](https://mathjs.org/docs/expressions/syntax.html)
- Implicit multiplication: `2 pi`, `(1+2)(3+4)`; binds tighter than `/` in most cases ("`20 kg / 4 kg` is 5, but `20 / 4 kg` is 5 kg"). [syntax](https://mathjs.org/docs/expressions/syntax.html)
- Custom functions: `math.import({ name: fn })`; a function with `rawArgs: true` receives unevaluated `Node[]` plus `math` and `scope`; a `toTex` property (template string with `${args[0]}` or `function(node, options)`) controls its LaTeX. [customization](https://mathjs.org/docs/expressions/customization.html)
- **Symbol resolution order** (source, `SymbolNode._compile`): function-argument names -> `scope.has(name)` -> `math[name]` -> valueless unit (`new Unit(null, name)`) -> `throw new Error('Undefined symbol ' + name)`. Scope always wins over units, so a user variable `m` or `N` shadows the unit. [SymbolNode.js](https://raw.githubusercontent.com/josdejong/mathjs/develop/src/expression/node/SymbolNode.js)
- Parser never constructs a `Unit`: `5 kN` is `OperatorNode('*', 'multiply', [ConstantNode(5), SymbolNode('kN')], true /* implicit */)`; the unit is resolved at evaluate time. [parse.js](https://raw.githubusercontent.com/josdejong/mathjs/develop/src/expression/parse.js)

### Units

- Creation `math.unit(45,'cm')` / `math.unit('0.1 kilogram')`; in expressions `5.4 kg`, conversion with `to` / `in` (`5 cm to mm`), `number(5 cm, mm)` strips to a number. [units](https://mathjs.org/docs/datatypes/units.html), [syntax](https://mathjs.org/docs/expressions/syntax.html)
- Dimensional analysis: `add` on units of different base throws `'Units do not match'`; `to()` throws ``Units do not match ('x' != 'y')``; valueless units in arithmetic throw `'Parameter x contains a unit with undefined value'`. Dimension vector has 9 slots (incl. ANGLE and BIT). [addScalar.js](https://raw.githubusercontent.com/josdejong/mathjs/develop/src/function/arithmetic/addScalar.js), [Unit.js](https://raw.githubusercontent.com/josdejong/mathjs/develop/src/type/unit/Unit.js)
- **Angles are NOT dimensionless**: `BASE_UNITS.ANGLE.dimensions = [0,0,0,0,0,0,0,1,0]`; `rad`, `deg`, `grad` (SHORT prefixes), `cycle`. Consequence reported in [issue #1585](https://github.com/josdejong/mathjs/issues/1585): an expression containing `rad` cannot be converted to `N` ("units mismatch"). Trig functions accept angle units. [Unit.js](https://raw.githubusercontent.com/josdejong/mathjs/develop/src/type/unit/Unit.js), [units](https://mathjs.org/docs/datatypes/units.html)
- Engineering-relevant units present (from the `UNITS` table): `N`/`newton` (SHORT prefixes -> `kN`, `MN` work), `kip`, `lbf`, `kilogramforce`, `dyn`; `Pa` with SHORT prefixes (-> `kPa`, `MPa`, `GPa`), `bar`, `psi`, `atm`, `torr`, `mmHg`; `J`, `Wh`, `BTU`, `eV`; `tonne` (LONG prefixes), `ton` (US short ton); length/mass/time/temperature etc. **No `tonf`, no `kNm`/`Nm` token** (`kNm` -> `SyntaxError: Unit "kNm" not found`; write `kN m` or `kN*m`). SI prefixes from quetta to quecto. [Unit.js](https://raw.githubusercontent.com/josdejong/mathjs/develop/src/type/unit/Unit.js), [units](https://mathjs.org/docs/datatypes/units.html)
- Custom units: `math.createUnit('furlong', '220 yards')`, options `definition`, `prefixes` (`none|short|long|binary_short|binary_long`), `offset`, `aliases`, `baseName`, `override`; omit definition to create a new base dimension; many at once via object map; unit names must start with a Latin letter and be alphanumeric unless `Unit.isValidAlpha` is overridden. [units](https://mathjs.org/docs/datatypes/units.html)
- Formatting: `format`/`toString` pick a best prefix; `toBest(unitList)` (added 14.6.0) restricts choice; `splitUnit(['ft','in'])`; `toSI()`. Compound units print with spaces and `/`: `'10 (kg m) / s^2'`, `'(kg m^2) / (s^2 mol)'` - never `·` or `*`. [Unit.js](https://raw.githubusercontent.com/josdejong/mathjs/develop/src/type/unit/Unit.js), [Unit.test.js](https://raw.githubusercontent.com/josdejong/mathjs/develop/test/unit-tests/type/unit/Unit.test.js), [HISTORY.md](https://raw.githubusercontent.com/josdejong/mathjs/develop/HISTORY.md)
- **Torque-as-joule trap.** `Unit.simplify()` matches the result's dimension vector against `UNIT_SYSTEMS.si` (`FORCE: N`, `ENERGY: J`, `PRESSURE: Pa`, ...) and takes the first match. A unit with a value whose `skipAutomaticSimplification` is `false` is simplified on `format()`. Units created from a string (`new Unit(5,'N m')`, i.e. anything typed by the user) keep their unit list (`skipAutomaticSimplificationDefault = true`), but `multiply`, `divide`, `pow` clear the flag, so `F * e` with `F = 5 kN`, `e = 2 m` is dimensionally ENERGY and will print as `10 kJ`. The maintainers' answer in [issue #2005 "Why Torque unit is not available?"](https://github.com/josdejong/mathjs/issues/2005) is "You can indeed create the units that you're missing yourself" (`math.createUnit("Nm", "1 N * m")`), with the note that torque "can also be expressed in joules/radian". Tests confirm `W·h` -> `J` after simplify and that `to()`/`toSI()` results skip simplification (`'24 in lbf rad'`). [Unit.js](https://raw.githubusercontent.com/josdejong/mathjs/develop/src/type/unit/Unit.js), [Unit.test.js](https://raw.githubusercontent.com/josdejong/mathjs/develop/test/unit-tests/type/unit/Unit.test.js)
- Other documented caveats: `math.unit` has its own parser, different from `math.evaluate`; `'8.314 m^3 Pa / mol K'` gives the wrong result because implicit multiplication has the same precedence as `*`/`/`; Celsius/Fahrenheit arithmetic is surprising. [units](https://mathjs.org/docs/datatypes/units.html)

### Matrices

Dense (default, n-dimensional) and sparse (2-D) matrices; `[1,2;3,4]` syntax, one-based inclusive indexing with `end` in expressions (zero-based in the JS API); broadcasting; "Matrices can contain different types of values: numbers, complex numbers, units, or strings." Linear algebra: `det, inv, pinv, lup, qr, slu, lusolve, usolve, lsolve, eigs, expm, sqrtm, schur, sylvester, lyap, trace, transpose, kron, cross, dot, ...`. [matrices](https://mathjs.org/docs/datatypes/matrices.html), [function index](https://mathjs.org/docs/reference/functions.html)

### Symbolic ("Algebra") capability - what exists, what does not

Full Algebra category: `derivative, leafCount, lsolve, lsolveAll, lup, lusolve, lyap, polynomialRoot, qr, rationalize, resolve, schur, simplify, simplifyConstant, simplifyCore, slu, sylvester, symbolicEqual, usolve, usolveAll`. **`solve` and `integrate` are not in the function index.** [function index](https://mathjs.org/docs/reference/functions.html)

- `simplify(expr, [rules], [scope], [options])`: rule-based rewriting; options `exactFractions` (default true), `fractionsLimit` (10000), `context` (`defaultContext` is "very permissive", e.g. `x/x -> 1`; `realContext`/`positiveContext` are value-preserving), custom rules as `'left -> right'` strings with wildcards `n, c, v`. Docs: "simplification is an inherently difficult problem", "it is undecidable whether a given expression is equivalent to zero". [simplify](https://mathjs.org/docs/reference/functions/simplify.html), [algebra](https://mathjs.org/docs/expressions/algebra.html)
- `derivative(expr, variable, {simplify})`: rule-based differentiation; "If there are multiple variables in the expression, it will return a partial derivative." Supported function list is not documented. [derivative](https://mathjs.org/docs/reference/functions/derivative.html)
- `rationalize(expr, [scope], [detailed])`: polynomial/rational normal form with coefficients for single-variable polynomials; fails on unresolved function calls (`sin(x)+y`). [rationalize](https://mathjs.org/docs/reference/functions/rationalize.html)
- `polynomialRoot(constant, linear, quadratic, cubic)`: **numeric**, "operates only on linear, quadratic, and cubic polynomials using the standard formulas". [polynomialRoot](https://mathjs.org/docs/reference/functions/polynomialRoot.html)
- `symbolicEqual(a, b)`: "simply checks if the difference of the two expressions simplifies down to 0"; a `false` is inconclusive. [symbolicEqual](https://mathjs.org/docs/reference/functions/symbolicEqual.html)
- `resolve(expr, scope)`: "replaces variable nodes with their scoped values" recursively - this is the primitive for the *substituted* line. [resolve](https://mathjs.org/docs/reference/functions/resolve.html)
- Linear systems are numeric only (`lusolve` on matrices). No symbolic equation solving, no integration, no factor/expand beyond what `simplify`/`rationalize` do. The README's "Does symbolic computation" claim refers to the above. [README](https://github.com/josdejong/mathjs)

### Tree -> LaTeX (`toTex`) and `toString`

- `node.toTex(options)` and `node.toString(options)` exist on every node; `toString` output is not the original input (`'3 + (4 * 2)'`). Options: `parenthesis: 'keep' | 'auto' | 'all'` (default `keep`), `implicit: 'hide' | 'show'`, `handler` (per-function map or a callback run for every node; returning nothing falls back to default). [expression trees](https://mathjs.org/docs/expressions/expression_trees.html), [customization](https://mathjs.org/docs/expressions/customization.html)
- Operators: `divide -> \frac{}{}`, `multiply -> \cdot`, implicit multiply -> `~` (non-breaking space) when `implicit:'hide'`, `pow` wraps both operands in braces, `transpose -> ^\top`, `unequal -> \neq`, parentheses as `\left( \right)`. Functions: `sqrt -> \sqrt{x}`, `cbrt -> \sqrt[3]{x}`, `nthRoot -> \sqrt[n]{x}`, `abs -> \left|x\right|`, `log(x,b) -> \log_{b}`, anything unknown -> `\mathrm{name}\left(args\right)`. [latex.js](https://raw.githubusercontent.com/josdejong/mathjs/develop/src/utils/latex.js), [OperatorNode.js](https://raw.githubusercontent.com/josdejong/mathjs/develop/src/expression/node/OperatorNode.js)
- Symbols (`SymbolNode._toTex`): if the name is not a math.js function/constant and `isValuelessUnit(name)` -> `toSymbol(name, true)` which returns `latexUnits[name]` (only `deg -> ^\circ`) or `\mathrm{<escaped name>}`; otherwise `latexSymbols[name]` (Greek names `alpha -> \alpha`, `Gamma -> \Gamma`, but `Alpha -> A`, `Beta -> B`, `Epsilon -> E`; `inf/Infinity/oo -> \infty`) or `escapeLatex(name)`. [SymbolNode.js](https://raw.githubusercontent.com/josdejong/mathjs/develop/src/expression/node/SymbolNode.js), [latex.js](https://raw.githubusercontent.com/josdejong/mathjs/develop/src/utils/latex.js)
- `escapeLatex` is the `escape-latex` package with `preserveFormatting: true`; its map escapes `_ -> \_`, `^ -> \textasciicircum{}`, `\ -> \textbackslash{}`, `{ } # $ % &`, and converts spaces to `~`. **So `M_Ed` renders as `M\_Ed` (literal underscore), not `M_{Ed}`.** This was deliberate: [issue #995](https://github.com/josdejong/mathjs/issues/995) - "`foo_{bar}` was intentional because it allows variable names with subscripts" was reverted in v4 (PR #1022) to escape everything; the suggested route for subscripts is overriding node `toTex` handlers, which the contributor called "quite intrusive and tedious". [escape-latex source](https://raw.githubusercontent.com/dangmai/escape-latex/master/src/index.js)
- Constants: numbers go through `format()`; `1.2e+6` becomes `1.2\cdot10^{6}`; strings -> `\mathtt{...}`; Fractions -> `toLatex()`; **a `Unit` value falls through `default: return value`** (raw `toString()` text, e.g. `10 kN m`, inside math mode). [ConstantNode.js](https://raw.githubusercontent.com/josdejong/mathjs/develop/src/expression/node/ConstantNode.js)
- No `Unit.toTex()`. [Issue #1849](https://github.com/josdejong/mathjs/issues/1849) was closed with the workaround `math.parse(math.format(value)).toTex()` -> `5~\mathrm{cm}`. The data type has no LaTeX formatter ([Unit.js](https://raw.githubusercontent.com/josdejong/mathjs/develop/src/type/unit/Unit.js) contains no `tex`).
- Unit-vs-variable collision in TeX: a scope variable named `m`, `N`, `A`, `d`, `h`, `g`, `L`, `V`, `W`, `F`, `C`, `B`, `b` ... is rendered `\mathrm{m}` etc. because `_toTex` only checks `math[name]` and `isValuelessUnit(name)`, not the scope. Evaluation is fine (scope wins), rendering is upright instead of italic. [SymbolNode.js](https://raw.githubusercontent.com/josdejong/mathjs/develop/src/expression/node/SymbolNode.js)
- KaTeX supports everything math.js emits: `\mathrm`, `\mathtt`, `\frac`, `\cdot`, `\left(...\right)`, `\sqrt[n]{}`, `\operatorname`, `\,`, `\textbackslash`, `\textasciicircum`, `\circ`, `\newline`. [KaTeX supported functions](https://katex.org/docs/supported)

### Notes per library

**Compute Engine (CortexJS / MathLive).** Positioning: "A JavaScript library for symbolic computing and numeric evaluation of mathematical expressions", parses LaTeX -> MathJSON and serializes back; `simplify`, `evaluate` (exact), `N` (numeric), `compile` to JS. [overview](https://mathlive.io/compute-engine/), [symbolic computing](https://mathlive.io/compute-engine/guides/symbolic-computing/). Calculus: `D` symbolic, `ND` numeric, `Integrate` "Evaluates to a symbolic indefinite integral", `NIntegrate` Monte Carlo numeric, `Limit`/`NLimit`. [calculus](https://mathlive.io/compute-engine/reference/calculus/). `solve()` is documented only through its rule tables: `solveRules` are "The rules used by `solve()` to find roots of univariate expressions", candidate roots are "validated against the original equation", `harmonizationRules` pre-rewrite equations; no published list of supported equation classes. [api.md](https://mathlive.io/compute-engine/api.md). Units: a real `Quantity` system with SI base/derived units and all prefixes (`kN`, `MPa` via prefix), `rad/deg/grad/turn`, `bar`, `atm`, `t`, `in/ft/lb`; `Add`/`Subtract` require compatible dimensions; `UnitConvert`, `UnitSimplify` (rewrites to a named derived unit when scale factor is 1 - note the same N·m -> J ambiguity exists by construction), `UnitDimension`, `IsCompatibleUnit`; LaTeX **input** forms `5\,\mathrm{m}`, `\qty{12}{cm}`, `\SI{5}{kg}`; "conversion between logarithmic and linear scales is not supported in v1". The docs do not show how a quantity is serialized back to LaTeX. Source files `units.ts`, `unit-data.ts`, `quantity-arithmetic.ts` exist in `main`. [units reference](https://mathlive.io/compute-engine/reference/units/), [library dir](https://github.com/cortex-js/compute-engine/tree/main/src/compute-engine/library). LaTeX serialization options: `multiply` (default `\times`), `invisibleMultiply`, `prettify`, `fractionStyle`, `digits: {significant|fractional}`, `notation: scientific|engineering|...`, `digitGroupSeparator` (default `\,`), `decimalSeparator` (e.g. `{,}`), `indexStyle: 'subscript'`. [latex syntax](https://mathlive.io/compute-engine/guides/latex-syntax/). Symbol naming (MathJSON spec): `/^[a-zA-Z_][a-zA-Z0-9_]*$/`, "Subscripts are indicated by an underscore `_` and superscripts by a double-underscore `__`", `alpha_0__prime -> \alpha_0^\prime`, `mu0 -> \mu_{0}`, multi-letter symbols "may be rendered with `\mathit{}`, `\mathrm{}` or `\operatorname{}`"; a symbol with no operands is written `\mathrm{Name}` unless `standaloneSymbol: true`. [MathJSON](https://mathlive.io/math-json/), [latex syntax](https://mathlive.io/compute-engine/guides/latex-syntax/). Changelog cadence is fast (0.146.0 and 0.147.0 both 2026-10-02, 0.148.0 2026-10-05, npm already at 0.153.0); recent entries touch Greek-name subscripts and `Solve` return semantics, i.e. the surface is still moving. [changelog](https://mathlive.io/compute-engine/changelog/). Risks: 1.2 MB gzip, pre-1.0 API, `node >= 22.3`, small community (482 stars), single-maintainer project.

**nerdamer 2.0.** "a new implementation" (TypeScript rewrite) with breaking changes vs 1.x; typed entry points `nerdamer/core|algebra|calculus|solve|structures`; `solve('x^2-1','x')` -> `SolutionSet`, `solveSystem([...])`, `integrate`, `simplify`, `toTeX()`. No units. 2.0.0 is on npm `latest` but GitHub shows no release entries. 83 open issues. [README](https://raw.githubusercontent.com/jiggzson/nerdamer/master/README.md), [GitHub](https://github.com/jiggzson/nerdamer)

**Algebrite.** CoffeeScript CAS (EigenMath lineage), bundle ~80 KB gzip, has `roots`, `integral`, `simplify`, `nroots` sources and a `printlatex` command (`printlatex(pi/2)` -> `\frac{\pi}{2}`, `printlatex(inv(a+1))` -> `{(1+a)}^{-1}`). npm 1.4.0 was published with Node 15 (2021); repo still gets pushes (2026-05) with 90 open issues; no TS types; "units of measurement" is claimed in the README without any documentation found. [README](https://raw.githubusercontent.com/davidedc/Algebrite/master/README.md), [tests](https://cdn.jsdelivr.net/npm/algebrite@1.4.0/tests/printlatex.coffee)

**Giac/Xcas.** Browser build "compiled with emscripten", optional WASM, "about 2 times slower for numeric code and up to 8 times slower for symbolic code than native Xcas", Chrome "about 5 times slower" than Firefox. GPL3 "for commercial dual-license contact us". No npm WASM package; the geogebra/giac repo provides Emscripten build scripts but publishes no sizes. Legal and bundle risk for a commercial product. [giac.html](https://www-fourier.univ-grenoble-alpes.fr/~parisse/giac.html), [xcasen](https://www-fourier.univ-grenoble-alpes.fr/~parisse/giac/xcasen.html), [geogebra/giac](https://raw.githubusercontent.com/geogebra/giac/master/README.md)

**SymPy via Pyodide.** Pyodide docs: "The full distribution is quite large (200+ megabytes)"; the CDN path is recommended and "cached by the browser"; packages load via `loadPackage`/`micropip`. No official load-time figures. The minimum network cost is the ~13.4 MB runtime plus the 6.3 MB SymPy wheel. Unsuitable for a PWA that should start instantly; viable only as an optional, lazily loaded "advanced" mode or on the CLI side (where you could just use real Python). [deploying](https://pyodide.org/en/stable/usage/downloading-and-deploying.html), [loading packages](https://pyodide.org/en/stable/usage/loading-packages.html)

## 3. What engineering calc tools actually need - the handcalcs approach

**handcalcs facts.** v1.11.0 (2026-01-23), Apache-2.0, 5,806 stars, 107 open issues, pushed 2026-10-14. Dependencies: `more_itertools`, `innerscope>=0.7.0`, `pyparsing` - **no SymPy dependency**. [PyPI JSON](https://pypi.org/pypi/handcalcs/json), [GitHub API](https://api.github.com/repos/connorferster/handcalcs)

**How it renders (from `src/handcalcs/handcalcs.py`).** No AST, no CAS. Each source line is tokenised with a pyparsing `infixNotation` grammar into nested deques, then run through two ordered substitution pipelines:

- Symbolic line, `swap_symbolic_calcs`: `insert_parentheses -> swap_custom_symbols -> swap_math_funcs -> swap_superscripts (** -> ^{}) -> swap_chained_fracs -> swap_frac_divs (/ -> \frac) -> swap_py_operators (* -> \cdot, % -> \bmod) -> swap_comparison_ops -> swap_for_greek -> swap_prime_notation -> swap_long_var_strs -> swap_double_subscripts (__ -> "\ ") -> extend_subscripts -> flatten_deque`.
- Numeric line, `swap_numeric_calcs`: same, plus `swap_values(pycode_as_deque, tex_results)` which looks each token up in the results dict and replaces it with the rendered value.
- Subscripts: `extend_subscripts` "ensures that any more than one subscript, e.g. s_ze, is included in the latex subscript notation" by inserting `{` after `_` and closing braces -> `M_Ed -> M_{Ed}`.
- Greek: `swap_for_greek` looks tokens up in `ChainMap(GREEK_LOWER, GREEK_UPPER)`; names containing underscores are split and converted per component; `greek_exclusions` opt-out.
- Values: `latex_repr(item, ...)` - arrays via `__len__`, SymPy objects via `__sympy__` -> `sympy.latex`, otherwise `item._repr_latex_()` with fallback `str(item)`; `$` stripped. This is the hook that unit libraries (forallpeople, pint) plug into.
- Numbers: `swap_scientific_notation_float` uses `"{:.{precision}e}"`, then `e+/e-` are rewritten to `\times 10^{...}`; `swap_dec_sep` for decimal comma.
- Conditionals are evaluated with `eval` on the kwargs.

[handcalcs.py](https://raw.githubusercontent.com/connorferster/handcalcs/main/src/handcalcs/handcalcs.py)

**What it supports / doesn't (README).** Long form (symbolic -> substituted -> result), short form, `params` columns, `symbolic` (no substitution), `sympy` mode, precision override, inline comments rendered, `sqrt` as radical, custom functions rendered as `\mathrm{name}(...)`, simple single-line conditionals, `scipy.quad` rendered as an integral if the function name contains `integrate`/`quad`. Not supported: anything spanning multiple lines (functions, `for`, `with`), lists/dicts, `//`, out-of-order cell execution. Units: "forallpeople ... was designed to work with handcalcs", "pint can work to good effect". [README](https://github.com/connorferster/handcalcs)

**forallpeople** (the unit lib handcalcs was designed with): each `Physical` stores SI base value + dimension vector; environments (JSON) define derived units like kN, Pa, MPa by dimension vector; auto-prefixing (500 mA, 1.2 kΩ); `.latex` / `.html` properties for rendering. [forallpeople](https://github.com/connorferster/forallpeople)

**Takeaway.** What a structural calc tool needs from "symbolic" math is almost entirely *typographic*: keep the expression tree the user typed, print it with proper `\frac`, `\sqrt`, `\cdot`, subscripts and Greek, print it again with numbers (plus units) substituted, print the result in a sensible unit. That is tree-walking plus a unit library plus number formatting. A CAS is only needed for the minority features - solving an equation for a variable, closed-form integration, simplification of a user-written formula - none of which handcalcs does, and none of which is in math.js either.

## 5. Rendering from an expression tree - known gaps

| Case | mathjs `toTex` | compute-engine `latex` |
|---|---|---|
| `M_Ed`, `f_yd` | `M\_Ed` (underscore escaped; intentional since v4, [#995](https://github.com/josdejong/mathjs/issues/995)) | `_` is the subscript marker: `alpha_0__prime -> \alpha_0^\prime`; `M_Ed` rendering unspecified in spec ("Ed" is not a listed modifier) but underscore -> subscript by rule ([MathJSON](https://mathlive.io/math-json/)) |
| Greek: `alpha`, `gamma_M0` | `alpha -> \alpha` only when the whole name is a Greek name; `gamma_M0 -> gamma\_M0` ([latex.js](https://raw.githubusercontent.com/josdejong/mathjs/develop/src/utils/latex.js)); typed Unicode `γ` passes through `escapeLatex` unchanged (KaTeX renders Unicode Greek) | Greek names map to commands; 0.148.0 changelog: Greek name without backslash "now takes a subscript into its name" ([changelog](https://mathlive.io/compute-engine/changelog/)) |
| Multi-letter variable `Ed`, `span` | italic run `Ed` (ambiguous with `E·d`) | `\mathrm{Name}` for operand-less symbols unless `standaloneSymbol` ([latex syntax](https://mathlive.io/compute-engine/guides/latex-syntax/)) |
| Variable named like a unit (`m`, `N`, `A`, `h`, `d`, `g`, `L`) | rendered `\mathrm{m}` (upright) because `toTex` checks `isValuelessUnit` not the scope ([SymbolNode.js](https://raw.githubusercontent.com/josdejong/mathjs/develop/src/expression/node/SymbolNode.js)) | n/a (units are explicit `Quantity` nodes) |
| Units in a formula `5 kN` | `5~\mathrm{kN}` via implicit-multiply `~` + `\mathrm` - acceptable | documented input forms `5\,\mathrm{m}`, `\qty{}{}`; output format not documented |
| Unit **results** (substituted line) | no `Unit.toTex`; `ConstantNode` holding a Unit emits raw `10 kN m` text ([ConstantNode.js](https://raw.githubusercontent.com/josdejong/mathjs/develop/src/expression/node/ConstantNode.js)); workaround `math.parse(math.format(u)).toTex()` ([#1849](https://github.com/josdejong/mathjs/issues/1849)) gives `10~\mathrm{kN}~\mathrm{m}` | not documented |
| Division | `\frac{}{}` always | configurable `fractionStyle` |
| Multiplication | `\cdot`; implicit -> `~` | `\times` default, configurable `multiply`, `invisibleMultiply` |
| Number formatting in LaTeX | `format()` with precision; exponent -> `\cdot10^{n}`; no thousands separator, no decimal-comma option in `toTex` | `digits`, `notation`, `digitGroupSeparator` (default `\,`), `decimalSeparator` `{,}` |
| Custom functions | `toTex` template/handler on imported function ([customization](https://mathjs.org/docs/expressions/customization.html)) | custom dictionary entries |
| Parenthesis control | `keep/auto/all` | - |

## Recommendation

**Engine for v1: math.js, wrapped - not used raw.** It is the only candidate that is small (197 KB gzip), mature (15k stars, 5.5k commits, release every ~2 months), Apache-2.0, TS-typed, Node 18+ and browser, and has a hackable expression tree with units and matrices in one package. Everything the handcalcs workflow needs is tree-walking, and math.js gives you `parse -> Node`, `resolve` for substitution, `evaluate(scope)` for results, `createUnit`, `toBest`, and per-node `toTex` handlers.

**Gaps you must close in a custom layer (all cheap, all required):**
1. **Own the LaTeX printer.** Write a ~200-line `Node -> LaTeX` walker instead of relying on `toTex` defaults (or use the `handler` callback). It must: turn `x_abc` into `x_{abc}` (handcalcs `extend_subscripts` rule), map Greek *components* of names (`gamma_M0 -> \gamma_{M0}`), decide upright vs italic from the scope (a scope variable is never a unit), and render Unit values as `10\,\mathrm{kN{\cdot}m}` with your display rules. Do not try to patch `escape-latex`.
2. **Own unit display.** Define engineering units up front (`createUnit('kNm','1 kN*m')` etc. - the maintainers' official answer) and apply a per-dimension preferred unit table (`moment -> kN m`, `line load -> kN/m`, `stress -> MPa`) before formatting; otherwise moments print as kJ. Decide angle policy: mathjs treats `rad` as a dimension, so either strip angles after trig or keep them out of products.
3. **Own statement semantics.** math.js functions are single-line and dynamically scoped; blocks are `;`/newline separated. Your document parser should split Markdown from math statements and feed one statement at a time to a persistent `math.parser()` so you control ordering, error locations and the three-line rendering per statement.
4. **No `solve`/`integrate`.** If a feature needs "solve for `d`" or closed-form integration, add it as an explicitly separate capability (numeric root-finding you write yourself for v1, or nerdamer 2.0 lazy-loaded: 127 KB gzip, Apache-2.0, `solve`/`integrate`/`toTeX`, but a fresh rewrite with 83 open issues and no units).

**Compute Engine is the serious alternative, not a complement.** It has what math.js lacks (symbolic `Integrate`, rule-based `solve`, real `Quantity` type with dimension vectors, LaTeX in *and* out with subscripts/Greek/number-formatting options). Costs: 1.18 MB gzip (6x math.js), pre-1.0 and churning (0.146 -> 0.153 within ~two weeks of October 2026), `node >= 22.3`, one maintainer, 482 stars, and its quantity -> LaTeX output is undocumented. Reasonable to prototype against if LaTeX-first input (MathLive editor) is on the roadmap; risky as the foundation of a PWA + CLI today.

**Reject:** Giac WASM (GPL-3 unless you pay for dual licensing, no published bundle sizes, Firefox-tuned), SymPy/Pyodide (~20 MB before caching, only sensible as an optional heavy mode), Algebrite (2021 npm release, no types, undocumented units), js-quantities / UnitMath / convert-units (dormant or not quantity algebra).

**Risks to state plainly:** math.js `toTex` is designed for generic math, not engineering typography - budget for the custom printer from day one. The unit simplifier's "first matching base" behaviour is a silent correctness-of-presentation bug for moments. Anything symbolic beyond `derivative`/`simplify` is not available without a second engine.
